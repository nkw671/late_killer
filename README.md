사용자 개인화 버스 도착 알림 시스템
<br>
<br>

# 설계 배경 <br>
왕복 3시간의 장거리 통학 환경에서 대중교통 도착 시간은 출석과 지각을 결정짓는 핵심 요인입니다. 특히 배차 간격이 긴 지역은 버스를 한 번 놓칠 경우 20분 이상의 대기 시간이 발생하여 심리적·시간적 손실이 큽니다.
<br><br>
기존 길찾기 앱들은 '경로 탐색'에 최적화되어 있어, 사용자가 특정 시간대에 자주 이용하는 정류장과 노선 정보를 실시간으로 추적하고 알림을 제공하는 기능은 부족합니다. 이러한 기존 앱의 한계점을 보완하여, 사용자가 설정한 특정 시간대에 탑승 예정 버스의 남은 시간을 지속적으로 안내하는 '사용자 개인화 버스 도착 알림 시스템' 아이디어를 떠올리게 되었습니다.
# 요구사항 분석
원시 요구사항:
<br><br>
정류장을 선택할 수 있어야한다<br>
특정 정류장을 경유하는 버스를 사용자가 선택할 수 있어야 한다.<br>
사용자가 알람 간격을 설정할 수 있어야 한다.<br>
정류장까지 걸리는 시간을 입력할 수 있어야한다. <br>
도착시간과 정류장까지 걸리는 시간을 고려하여 지금 출발해야한다는 알림이 출력되어야한다.<br>
버스 도착 정보를 tts 음성으로 안내해야한다.<br>
요일별로 알림 시간을 설정할 수 있어야한다. <br>
선택한 버스 중 가장 빨리 도착하는 버스를 기준으로 알림을 출력해야한다. <br>
가장 빠른 버스가 지나가면 다음으로 가장 빨리 도착하는 버스로 자동 전환되어야한다. <br>
잠금화면에서 바로 볼 수 있어야한다.<br>
다른 앱 사용 중에도 볼 수 있도록 플로팅 화면을 지원해야한다.<br>

-----------------------------------

요구사항 품질 요소를 고려하여 재작성된 요구사항 분석:

| 등급 | 설명 |
|------|------|
| P1 필수 | 미구현시 기능에 지장이 가는 요구사항 |
| P2 중요 | 전체 기능에는 영향을 미치지 않지만 사용성에 지장을 주는 요구사항 |
| P3 선택 | 사용자 기호 편의기능 |

| ID | 분류 | 요구사항 | 우선순위 | 테스트 기준 |
|----|------|----------|----------|-------------|
| REQ-01 | 정류장 선택 | 사용자는 정류장을 이름으로 검색할 수 있어야 한다. | P1 필수 | 존재하는 정류장 이름 입력 시 해당 정류장이 결과에 표시됨을 확인. 존재하지 않는 이름 입력 시 "결과 없음" 메시지 표시 확인 |
| REQ-02 | 정류장 선택 | 사용자는 정류장을 번호로 검색할 수 있어야 한다. | P1 필수 | 존재하는 정류장 번호 입력 시 해당 정류장이 결과에 표시됨을 확인. 존재하지 않는 번호 입력 시 "결과 없음" 메시지 표시 확인 |
| REQ-03 | 정류장 선택 | 사용자는 검색된 정류장을 즐겨찾기로 등록할 수 있어야 한다. 등록 가능한 정류장 수의 상한은 없다. | P1 필수 | 정류장 1개·10개 등록 후 즐겨찾기 목록에 표시됨을 확인 |
| REQ-04 | 정류장 선택 | 사용자는 즐겨찾기에 등록된 정류장을 삭제할 수 있어야 한다. | P1 필수 | 등록된 정류장 삭제 후 즐겨찾기 목록에서 제거됨을 확인 |
| REQ-05 | 버스 선택 | 사용자는 등록된 정류장을 경유하는 버스 노선 목록을 조회할 수 있어야 한다. | P1 필수 | 정류장 선택 시 해당 정류장 경유 노선 목록이 표시됨을 확인 |
| REQ-06 | 버스 선택 | 사용자는 조회된 버스 노선 목록에서 알람에 사용할 노선을 하나 이상 선택할 수 있어야 한다. | P1 필수 | 노선 1개·3개 선택 후 저장 성공 확인. 노선 미선택 상태에서 저장 시 오류 메시지 표시 확인 |
| REQ-07 | 알람 설정 | 사용자는 정류장까지 도보로 이동하는 소요 시간을 1분 단위로 입력할 수 있어야 한다. 허용 범위는 1분 이상 60분 이하이다. | P1 필수 | 1분·30분·60분 입력 시 저장 성공 확인. 0분·61분 입력 시 오류 메시지 표시 확인 |
| REQ-09 | 알람 설정 | 사용자는 알람을 요일별(월·화·수·목·금·토·일)로 독립적으로 활성화 또는 비활성화할 수 있어야 한다. | P1 필수 | 수·금요일만 활성화 후 화요일에 알람이 발생하지 않음을 확인 |
| REQ-10 | 알람 설정 | 사용자는 요일별로 알람을 발생시킬 시작 시간을 HH:MM 형식으로 설정할 수 있어야 한다. 요일마다 서로 다른 시각을 설정할 수 있어야 한다. | P2 중요 | 월요일 08:00·화요일 09:30 설정 후 각 요일에 해당 시각 부터으로 알람 발생 확인 |
| REQ-11 | 알림 로직 | 앱은 REQ-06에서 선택된 버스 노선 중 예정 도착 시각이 가장 이른 버스를 알림 기준 버스로 설정해야 한다. | P1 필수 | 도착 예정 시각이 각각 5분·10분·15분 후인 노선 3개 선택 시 5분 후 도착 노선이 기준 버스로 설정됨을 확인 |
| REQ-12 | 알림 로직 | 앱은 알림 기준 버스의 예정 도착 시각에서 도보 소요 시간(REQ-07)을 뺀 시각이 현재 시각과 같아지는 순간, "지금 출발해야 합니다" 알림을 1회 발생시켜야 한다. | P1 필수 | 도착 예정 10분 후·도보 10분 설정 시 현재 시각에 알림 정확히 1회 발생 확인. 동일 조건에서 알림이 2회 이상 발생하지 않음을 확인 |
| REQ-13 | 알림 로직 | 알림 기준 버스가 해당 정류장을 통과한 것으로 확인되면, 앱은 REQ-06에서 선택된 나머지 노선 중 다음으로 예정 도착 시각이 이른 버스를 새로운 알림 기준 버스로 자동 전환해야 한다. 통과 여부는 실시간 API 응답에서 해당 노선의 도착 정보가 소멸된 것으로 판단한다. | P1 필수 | 기준 버스 통과 시뮬레이션(API 응답에서 해당 노선 제거) 후 다음 버스로 기준 전환됨을 확인 |
| REQ-14 | 알림 로직 | REQ-13의 자동 전환 시점에 전환할 노선이 더 이상 존재하지 않으면, 앱은 알림을 중단하고 사용자에게 "오늘 선택한 버스가 모두 지나갔습니다" 메시지를 1회 표시해야 한다. | P1 필수 | 선택 노선 1개만 존재하는 상태에서 해당 버스 통과 시뮬레이션 후 알림 중단 및 메시지 표시 확인 |
| REQ-15 | 알림 로직 | 앱은 알람이 활성화된 동안 실시간 API를 상시 호출하여 버스 도착 정보를 갱신해야 한다. API 호출 간격은 10초 이하이어야 한다. | P1 필수 | 알람 활성화 후 10초 이내에 API가 재호출됨을 네트워크 로그로 확인. 알람 비활성화 후 API 호출이 중단됨을 확인 |
| REQ-16 | TTS 안내 | 앱은 REQ-12의 알림 발생 시 기기의 기본 TTS 엔진을 사용하여 알림 기준 버스의 노선 번호를 한국어로 음성 출력해야 한다. | P1 필수 | TTS 출력 텍스트에 노선 번호 포함 여부 확인 |
| REQ-17 | TTS 안내 | 앱은 REQ-12의 알림 발생 시 기기의 기본 TTS 엔진을 사용하여 알림 기준 버스의 예정 도착까지 남은 시간(분)을 한국어로 음성 출력해야 한다. | P1 필수 | TTS 출력 텍스트에 남은 시간(분) 포함 여부 확인 |
| REQ-18 | TTS 안내 | 사용자는 TTS 음성 안내의 볼륨을 시스템 미디어 볼륨과 독립적으로 0%에서 100% 사이에서 조절할 수 있어야 한다. | P2 선택 | 볼륨 0% 설정 시 TTS 무음 출력 확인. 100% 설정 시 시스템 볼륨 기준 최대 출력 확인 |
| REQ-19 | 잠금화면 | 앱의 알림은 Android 잠금화면에 알림 기준 버스의 노선 번호와 예정 도착 시각을 포함하여 표시되어야 한다. | P2 중요 | Android 기기 잠금 상태에서 알림 발생 후 노선 번호·도착 시각 표시 여부 확인 |
| REQ-20 | 잠금화면 | 앱의 알림은 iOS 잠금화면에 알림 기준 버스의 노선 번호와 예정 도착 시각을 포함하여 표시되어야 한다. | P2 중요 | iOS 기기 잠금 상태에서 알림 발생 후 노선 번호·도착 시각 표시 여부 확인 |

| REQ-22 | 플로팅 화면 | 앱은 사용자가 다른 앱을 사용하는 중에도 알림 기준 버스의 예정 도착까지 남은 시간을 MM:SS(분:초) 형식으로 REQ-15의 API 갱신 주기에 맞추어 실시간으로 갱신하여 플로팅 UI에 표시해야 한다. | P2 중요 | 타 앱 실행 중 API 갱신 후 10초 이내에 플로팅 UI의 남은 시간이 MM:SS 형식으로 갱신됨을 확인 |
